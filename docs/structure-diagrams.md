# Structure diagrams

The directory and analysis views use the same `StructurePanel`. It appears after
instance navigation, before detailed definitions or result controls. Family pages
show a shared structure and compact instance comparison. Concrete instances use
parameter-bound drawings. The overview is initially selected; a second view
explains the round or internal construction. Keyboard-accessible enlargement,
collapse, scientific captions and SVG/LaTeX downloads are included. Headings have
no explanatory subtitle. Family views omit the parameter sidebar; instance views
show their parameters once, alongside the figure. Full definitions remain
available on demand. Sources and drawing attribution share one disclosure.
Narrow screens receive separately authored vertical overview SVGs through
`picture`; complex detail views remain scrollable at a readable size. A scroll
hint appears only when the active detail image actually overflows its container.

## Sources and scope

`data/primitives/diagrams.json` is the closed, authored registry. Each family
explicitly lists supported instance IDs, versioned specifications, precise
locations, design references and review state. A source check is not an
independent human review or a security endorsement. The IACR-hosted
[TikZ for Cryptographers](https://www.iacr.org/authors/tikz/) gallery informs the
visual conventions; these are original Atlas drawings, not copied paper figures.
No gallery source, custom package or paper PDF is vendored. Specifications take
precedence where an original design differs from the catalog's edition.

The library covers AES, TDEA, IETF ChaCha20, SHA-2, SHA-3, SHAKE, Keccak,
standardized Ascon-AEAD128, IETF ChaCha20-Poly1305 and AES-CMAC. Overall structure
and internal detail remain separate. Important distinctions include AES's final
round and key expansion, SHA-2 instance-specific IVs, SHA-3/SHAKE domain suffixes,
Keccak-p's last-round convention, and Ascon's standardized bit ordering.

Additional bindings cover SM3, SM4, Camellia, ARIA, SEED, PRESENT, Salsa20,
SHA-1 and MD5. Their drawings retain algorithm-specific boundaries: SM3 uses
XOR feed-forward; SM4 reverses the final words and uses distinct data/key linear
maps; Camellia inserts FL layers only between six-round groups; ARIA omits final
diffusion; SEED omits the final half exchange; PRESENT has a final key addition
after 31 SP rounds. The Salsa20 drawings use column/row rounds. Historical hash
views retain their security context and distinguish MD5's little-endian encoding
from SHA-1/SM3's big-endian encoding. Shared hash templates derive the chaining
word count, step count, feed-forward operator and serialization from each binding.

Only explicit catalog bindings are eligible. Standard AES diagrams are never
inferred for research variants. Filtering reduced-round attacks does not redefine
the primitive or invent an attack's round boundaries. Public figures depend only
on public definitions, never analysis records.

## Authoring and generation

Authored sources and the common theme are in `docs/figures/primitives/`.
The theme uses restrained teal, thin lines and standard mathematical operators.
Shapes and labels carry meaning independently of color. Fonts are outlined in
SVG; the HTML caption supplies a readable alternative.

```sh
npm run diagrams:build
npm run check:diagrams
npm run diagrams:verify
```

Generation requires a local TeX distribution with `latex`, `standalone`, `tikz`,
`lmodern`, `amsmath`, `amssymb` and `dvisvgm`. It reads only trusted checked-in
templates. Each batch runs in a fresh temporary workspace with shell escape
disabled, restrictive TeX file access and a 30-second process timeout. Compilation
does not fetch packages or execute browser-supplied TeX.

`lib/node/primitive-diagrams.cjs` derives parameter macros from the public
catalog. Avoid duplicating variable instance parameters in templates. Family
macros are symbolic only when the bound instances differ. Each downloaded `.tex`
is self-contained apart from the standard TeX packages.

Generated SVG and TeX files live in `public/figures/primitives/`.
`data/primitives/diagram-assets.json` records exact toolchain versions, parameter,
template/generator, SVG and TeX hashes, and image dimensions. Regenerate with the
recorded toolchain for reproducible figures; a toolchain upgrade requires reviewing
the resulting visual diff. Do not edit generated files by hand.
`diagrams:verify` checks the recorded toolchain before recompiling and comparing
every generated byte, without writing to the source tree. Ordinary CI checks
committed artifacts; a maintainer can run this additional regeneration check in
the recorded TeX environment.

Ordinary `npm ci`, builds, CI checks and browsing need no TeX installation.
Committed assets are validated against the registry, source and catalog. SVGs use
a closed, inert element/attribute vocabulary: no scripts, external references,
fonts, CSS or interactive elements. The frontend loads them as images. Release
checks also compare the emitted manifest and every SVG/TeX asset with the checked
source. Manifest hashes participate in the public data revision.

## Review checklist

- Check the exact edition, operation order, state layout, key path, phase
  boundaries, final block/round, padding and domain separation.
- Check every explicit instance binding; retain a pending notice for unreviewed
  variants. Do not reinterpret scientific records while drawing.
- Inspect overview and detail views at normal size and enlarged, including
  desktop, 320/375-pixel screens, keyboard navigation and grayscale readability.
- Run `npm run check`, `npm run build`, `npm run check:release`, affected browser
  tests and local-profile routing checks when available.

Original drawing code and generated figures follow the repository's Apache-2.0
license. Registry/editorial metadata follows the dataset license. External papers,
standards and gallery material retain their own rights.
